## 1. 操作系统（OS）

操作系统是控制和管理整个计算机系统的**硬件和软件资源**，并合理地组织调度计算机的工作和资源的分配：

- **系统资源的管理者** → 处理机管理、存储器管理、文件管理、设备管理（目标：安全、高效）
- **向上层提供方便易用的服务** → 封装复杂硬件功能
- **最接近硬件的系统软件**

### 例子：QQ 视频聊天

| 步骤 | 涉及功能 |
|------|---------|
| 找到 QQ 安装位置 | 文件管理 |
| 双击打开 QQ.exe | 存储器管理 |
| QQ 程序正常运行 | 处理机管理 |
| QQ 视频聊天 | 设备管理 |

### 向上层提供的服务

| 服务类型 | 说明 |
|---------|------|
| **GUI** | 图形化用户接口 |
| **联机命令接口** | 交互式，用户说一句，系统做一句 |
| **脱机命令接口** | 批处理，用户说一堆，系统做一堆 |
| **程序接口** | 系统调用，由一系列系统调用组成 |

## 2. OS 的特征

**并发、共享**（两个最基本特征，互为存在条件）、虚拟、异步。

### 2.1 并发性

- **并发**：两个或多个进程在**同一时间间隔内**运行（宏观同时，微观交替）
- **并行**：两个或多个进程在**同一时刻**同时运行

### 2.2 共享

| 方式 | 说明 | 例子 |
|------|------|------|
| **互斥共享** | 一段时间内只允许一个进程访问 | 摄像头 |
| **同时共享** | 多个进程"同时"访问 | QQ 和微信同时发送文件 |

### 2.3 虚拟

把一个**物理实体**变为若干个**逻辑对应物**：
- **虚拟存储器**（空分复用技术）
- **虚拟处理器**（时分复用技术）

### 2.4 异步

进程执行**走走停停**，以不可预知的速度向前推进。但运行环境相同时，OS 保证多次运行获得相同结果。

## 3. OS 的发展史

| 阶段 | 特点 |
|------|------|
| **手工操作** | 人机速度矛盾，资源利用率极低 |
| **单道批处理** | 引入脱机 I/O，缓解人机矛盾，但内存仅一道程序 |
| **多道批处理** | OS 诞生，多道程序并发，资源利用率大幅提升，但无交互 |
| **分时 OS** | 时间片轮转，人机交互，但无法优先处理紧急任务 |
| **实时 OS** | 及时性和可靠性，优先响应紧急任务 |
| **网络 OS** | 资源共享和通信 |
| **分布式 OS** | 分布性和并行性，各计算机地位相同 |
| **个人计算机 OS** | Windows、MacOS |

### 实时操作系统

- **硬实时**：必须在规定时限内完成（导弹控制系统）
- **软实时**：允许偶尔违反时间规定（12306 订票系统）

## 4. OS 的运行机制

### 两类程序

| 程序 | 指令 | 运行状态 |
|------|------|---------|
| **内核程序** | 特权指令 + 非特权指令 | 内核态（管态）|
| **应用程序** | 非特权指令 | 用户态（目态）|

### CPU 状态切换

| 方向 | 方式 |
|------|------|
| 内核态 → 用户态 | 执行修改 PSW 的**特权指令** |
| 用户态 → 内核态 | 由**中断**引起，硬件自动完成 |

### 中断的作用

使 CPU 由**用户态切换到内核态**，是 OS 夺回 CPU 使用权的**唯一途径**。

#### 内中断（异常）

| 类型 | 说明 | 例子 |
|------|------|------|
| **陷阱/陷入（trap）** | 应用程序故意引发 | 系统调用（通过陷入指令实现）|
| **故障（fault）** | 错误条件，可能被修复 | 缺页故障 |
| **终止（abort）** | 致命错误，无法修复 | 除数为 0、执行特权指令 |

#### 外中断

- 时钟中断
- I/O 中断请求

### 中断机制原理

CPU 检测到中断信号 → 查询**中断向量表** → 找到对应的中断处理程序。

## 5. 系统调用

OS 提供给应用程序使用的接口，用于请求内核服务。

### 与库函数的区别

| 层次 | 内容 |
|------|------|
| 应用程序 | 可直接系统调用，也可使用库函数 |
| 编程语言 | 将系统调用封装为库函数 |
| 操作系统 | 提供系统调用 |
| 裸机 | — |

### 按功能分类

| 类型 | 功能 |
|------|------|
| 设备管理 | 请求/释放/启动设备 |
| 文件管理 | 读/写/创建/删除文件 |
| 进程控制 | 创建/撤销/阻塞/唤醒进程 |
| 进程通信 | 消息传递/信号传递 |
| 内存管理 | 分配/回收内存 |

### 系统调用过程

传递参数 → 执行 `trap` 指令（用户态）→ 执行内核处理程序（核心态）→ 返回应用程序

> `trap` 指令在用户态执行，引发内中断使 CPU 进入核心态。

## 6. OS 的体系结构

### 大内核（宏内核）

| 优点 | 缺点 |
|------|------|
| 高性能 | 代码庞大、结构混乱、难以维护 |

### 微内核

只包含：时钟管理、中断处理、原语。

| 优点 | 缺点 |
|------|------|
| 结构清晰、方便维护 | 频繁切换状态，性能低 |

> CPU 状态切换有成本，频繁切换会降低系统性能。
